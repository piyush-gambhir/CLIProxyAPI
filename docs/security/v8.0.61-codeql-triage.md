# v8.0.61 CodeQL triage

PR: https://github.com/piyush-gambhir/CLIProxyAPI/pull/4

The upgrade keeps all required checks and the security-extended queries enabled. Findings are reviewed against source and SARIF data flow. Existing alerts are not automatically accepted merely because they exist on main. This report records confirmed false positives separately from code fixes and pending findings.

## Confirmed defects fixed

- Cooldown JSON fallback no longer interpolates unescaped strings.
- The shared log formatter escapes CR, LF, ESC and Unicode line separators after assembling all fields. CLI identity/error output quotes untrusted strings.
- Provider token limits reject negative or unrepresentable integers.
- Claude and Codex success pages reject non-web links and escape HTML attribute delimiters.
- Byte-buffer preallocation sums use checked arithmetic; quoted-key scratch buffers avoid overflowing length additions.

Focused tests cover hostile log messages/fields, integer bounds, HTML attributes and script URLs, and capacity overflow. Existing protocol and persistence suites exercise assembled payloads and account storage.

## Confirmed false positives

SHA-256 sites below implement identifiers, change fingerprints, or cache namespaces. None implements low-entropy password verification. Replacing these with password KDFs would change persistent identifiers and cache behavior without addressing the reported weakness. Management password verification actually uses bcrypt in `internal/api/handlers/management/handler.go`.

Rust examples receive a host-owned ABI table. `internal/pluginhost/loader_unix.go` allocates it with C malloc and deliberately retains both table/context after logical close; Windows retains resident state in `internal/pluginhost/loader_windows.go`. `call_host` checks the pointer for null. The analyzer cannot connect this foreign allocation lifetime to the saved pointer.

The generic management HTTP tool is intentionally restricted to a trusted administrator. Its outbound URL parameter is the tool's contract, not a public proxy endpoint. Authentication remains enforced by `Handler.Middleware` and `AuthenticateManagementKey`; no network allowlist or authentication rule was removed.

## Additional data-flow review after fixes

Source: Go analysis 2129132826, after the HTML, quoting and byte-capacity fixes. Required checks and query configuration remain unchanged.

- Logrus sinks execute before the shared formatter. The formatter now escapes all control runes in the final assembled line. CLI printf sinks quote untrusted strings instead. Per-request transcripts are isolated files containing intentionally raw request bodies; management routes are excluded and headers are masked.
- Cleartext findings overapproximate entire Header and attribute maps. Reviewed selected values are conversation/session/request identities, numeric counts, masked project/API-key diagnostics, environment variable names, or stable auth IDs. API-key client IDs are generated by the SHA-256 synthesizer. Neither HTTP Authorization nor the value read by os.Getenv flows into these selected identities.
- HTTP auth filenames reject separators and dot-directory names. Upload paths use filepath.Base under AuthDir; buildAuthFromFileData assigns ID/FileName/path rather than trusting JSON metadata. Subsequent token writes, registry updates and watcher/store mirrors consume these assigned paths. Absolute paths in the SDK are a trusted caller contract, not an HTTP file-path parameter. OAuth callback filenames separately validate both provider and state.
- Six remaining XSS sinks are generic JSON/SSE writer wrappers. The actual unescaped HTML success-page sinks have been corrected and no longer appear. Escaping arbitrary protocol bytes in middleware would corrupt API responses.
- Remaining allocation warnings count existing map or slice entries, not arbitrary byte lengths. String/byte-slice and map entries consume multiple machine words, bounding their possible count well below MaxInt. Stream channel capacity combines two already allocated byte-slice lists plus at most one slot. Byte-length arithmetic was corrected separately.
- Queue pop count is clamped to the existing queue length under its mutex. HTTP chunk conversion is bounded by the remaining int-sized input slice. Provider numeric conversion now checks platform bounds.
- Callback redirects have a fixed absolute loopback origin before path/query data is appended. Leading path slashes cannot turn this absolute URL into a different host.
